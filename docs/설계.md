# koja 설계 (v0.1, 2026-11-23)

요구사항 원문: `docs/private/요구사항.md`(비공개, 로컬 전용)

## 1. 확정 사항

| 항목 | 결정 |
|---|---|
| 형태 | 윈도우·맥 설치형 데스크톱 앱, 팀 내부 몇 명 배포 |
| 언어·UI | Java 25 LTS + JavaFX, Gradle, jpackage(.msi / .dmg) |
| 빌드 | GitHub Actions 매트릭스(windows-latest, macos-latest arm64). jpackage는 크로스 빌드 불가 |
| 서명 | 1차는 미서명 + 설치 안내 문서 |
| AI 단계 | 단계마다 로컬/외부 선택. **로컬을 먼저 구현**, 외부 어댑터는 나중 |
| 로컬 LLM | llama.cpp `llama-server`를 앱에 내장(Win CUDA / Mac Metal). OpenAI 호환 API로 호출 |
| 로컬 STT·화자 구분 | **0단계 PoC로 비교 후 결정** (후보는 7장) |
| 검수 | 앱 안에서 먼저(영상 + 표), 이후 Google 시트로 내보내기 |
| 시트 인증 | OAuth Desktop(루프백 + PKCE) + `drive.file` 스코프, 사용자별 구글 계정 |
| 분야 | 발로란트 우선. 용어집은 게임별 파일로 분리해 확장 가능하게 |
| 범위 밖 | 일본어 발화의 한국어 번역(6-3). 나중에 옵션으로 추가 |

각 결정의 이유와 버린 대안은 [결정기록.md](결정기록.md)에 있다.

## 2. 핵심 원칙

1. **타임라인과 한국어 원문은 STT 결과에서만 나온다.** LLM은 STT 구간 ID를 묶고, 분류하고, 번역만 한다. LLM 출력은 코드로 검증한다(모든 구간 ID가 순서대로 한 번씩 쓰였는지).
2. **단계마다 결과를 파일로 남긴다.** 실패하거나 엔진을 바꿨을 때 그 단계부터 다시 돌릴 수 있게.
3. **GPU는 한 번에 한 단계만 쓴다.** STT → 화자 구분 → LLM 순서로 돌리고, 각 엔진은 단계가 끝나면 내린다. 8GB 카드 기준으로 맞춘다.
4. **모르면 비워 두고 표시한다.** 화자 이름, 청취 불명 구간은 추측하지 않고 플래그를 단다.

## 3. 구조

```
JavaFX 앱 (한 프로세스)
├─ ui        가져오기 · 진행 상황 · 검수 화면(영상+표) · 설정
├─ core      Project 모델, project.json 저장/로드, 파이프라인 실행, 검증기
├─ engine    단계별 인터페이스 + 로컬/외부 구현
│   ├─ Transcriber   (로컬: PoC 결과 / 외부: Soniox, CLOVA …)
│   ├─ Diarizer      (로컬: PoC 결과 / 외부: STT 내장)
│   ├─ LlmClient     (로컬: llama-server / 외부: Gemini, Claude, OpenAI)
│   └─ FrameReader   (로컬: llama-server 비전 모델 / 외부: Gemini)
├─ media     ffmpeg 호출(오디오 추출, 프록시 MP4, 프레임 추출)
├─ runtime   내장 바이너리·모델 관리(다운로드, 체크섬, 실행/종료)
└─ export    Google Sheets 출력
```

Gradle 단일 모듈(`app/`, Java 모듈 `koja`), 패키지 `koja.*`로만 나눈다. 쪼갤 이유가 생기면 그때 모듈로 뺀다.

### 내장 바이너리와 모델

- 앱 번들: `ffmpeg`(LGPL 빌드), `llama-server`(Win: CUDA 빌드 + cudart DLL / Mac: Metal 빌드). CI에서 고정 버전과 체크섬으로 받아 넣는다.
- 모델(GB 단위)은 번들에 넣지 않는다. 첫 실행 때 Hugging Face에서 받아 사용자 데이터 폴더에 둔다.
  - Win: `%LOCALAPPDATA%\koja\models` / Mac: `~/Library/Application Support/koja/models`
- 로컬 STT 엔진이 Python 워커로 결정되면 앱과 별도로 설치하는 선택 모듈로 둔다(uv로 환경 구성). 앱은 stdin/stdout JSON으로 부른다.

## 4. 처리 흐름

| # | 단계 | 입력 → 출력 | 비고 |
|---|---|---|---|
| 1 | 가져오기 | 영상 → `audio.wav`(16kHz mono), `proxy.mp4`(H.264 720p, GOP 1초) | 프록시는 검수 화면 재생용. 원본 포맷 무관 |
| 2 | STT | audio → `stt.json` (구간: id, startMs, endMs, text, lang, 단어 시간) | VAD로 무음·BGM 구간 환각 억제 |
| 3 | 화자 구분 | audio → `diar.json` (화자 턴) → STT 구간에 speakerId 부여(겹침 최대) | 화자 수 범위 지정 가능 |
| 4 | 일본어 구간 | STT 언어 태그 / 구간별 언어 감지 → `ja` 구간은 일본어로 재전사 | 일본인 인터뷰어 질문용 |
| 5 | 구조화 (LLM) | 3~5분 청크 + 앞뒤 겹침 → `rows.json` | 영상 유형 판별, 문장 단위 묶기, 질문/답변 분류, 불확실 플래그 |
| 6 | 화자 이름 (비전) | 화자별 첫 발화 시점 프레임의 하단 크롭 → 이름 후보 | 못 찾으면 `화자 미확인 N` + 플래그 |
| 7 | 번역 (LLM) | rows + 용어집 + 화자표 + 직전 문맥 → 각 행 `ja` | 행 ID 단위 대응 검증 |
| 8 | 검수 | 사람이 앱에서 수정·플래그 해제 | 행 클릭 → 영상 이동 |
| 9 | 내보내기 | Google 시트 생성 + 서식 | `batchUpdate` 1~2회 |

영상 유형(질의응답·자유 발언·혼합, 인터뷰어 국적)은 5단계에서 자동 판별하고, 가져올 때 사용자가 직접 지정할 수도 있다.

## 5. 데이터 모델 (`project.json`)

```jsonc
{
  "version": 1,
  "source": { "path": "...", "durationMs": 3600000 },
  "meta": { "title": "", "topic": "", "participants": [] },
  "videoType": "INTERVIEW_JA | INTERVIEW_KO | FREE | MIXED",
  "speakers": [ { "id": "S1", "name": "선수A", "confirmed": true },
                { "id": "S2", "name": "화자 미확인 1", "confirmed": false } ],
  "sttSegments": [ { "id": 1, "startMs": 398000, "endMs": 401200,
                     "text": "...", "lang": "ko", "speakerId": "S1" } ],
  "rows": [ { "id": "r1",
              "kind": "LINE | QUESTION_KO | QUESTION_JA",
              "startMs": 398000,          // QUESTION_JA 는 null
              "speakerId": "S1",          // QUESTION_JA 는 null
              "ko": "...", "ja": "...",
              "segIds": [1, 2],
              "flags": ["SPEAKER_UNSURE", "TEXT_UNSURE"] } ],
  "glossary": "valorant",
  "stages": { "stt": { "engine": "...", "done": true } }
}
```

- `startMs`는 해당 행 첫 STT 구간의 시작값을 그대로 쓴다. LLM이 정하지 않는다.
- 코드: `koja.core.Project`(레코드), 읽기·쓰기는 `ProjectStore`. 저장은 임시 파일에 쓴 뒤 바꿔치기한다(쓰다 죽어도 기존 파일 보존). `version`이 다르면 읽지 않는다.
- 표시 형식: `m:ss`, 1시간 넘으면 `h:mm:ss` (**미확정, 기본값**)

## 6. 로컬 LLM 기본값 (PoC로 확인)

| 장비 | 구조화·비전 | 번역 |
|---|---|---|
| 8GB / 10GB + RAM 32GB | Qwen3.5-9B Q4 (GPU에 전부) | Gemma 4 26B-A4B Q4, MoE 전문가 일부 CPU 오프로드 |
| M5 Pro 24GB | Qwen3.5-9B Q4 | Gemma 4 26B-A4B Q4 (메모리 상한 근처, 청크 작게) |

로컬 번역 품질은 상용 모델보다 낮을 것으로 예상한다(공개 벤치 1건 근거). 번역 단계만 외부로 바꾸는 게 첫 외부 어댑터 후보.

## 7. 0단계 PoC (로컬 엔진 결정)

목적: 같은 샘플로 로컬 후보를 재고 엔진을 고른다. Python 스크립트로 빠르게 하고, 앱 코드와는 분리한다(`poc/`).

**필요 데이터**: `docs/private/샘플요청.md`(비공개)의 A-1(일본인 인터뷰어) 1편 + B(자유 발언) 1편, 각 20분 이상 + 사람이 만든 완성 시트.

| 비교 대상 | 후보 |
|---|---|
| STT | Qwen3-ASR-1.7B, 한국어 파인튜닝판(TeamUNIVA), Whisper large-v3-turbo(whisper.cpp), sherpa-onnx Qwen3-ASR |
| 화자 구분 | pyannote community-1, sherpa-onnx 화자 구분 |
| 번역 | Gemma 4 26B-A4B, Qwen3.5-9B, Gemma 4 E4B (llama-server) |

| 측정 항목 | 방법 |
|---|---|
| 한국어 정확도 | 정답 시트 C열 대비 CER |
| 시간 정확도 | 행 시작 시각 오차 중앙값, 1초 이내 비율 |
| 화자 정확도 | 행 단위 화자 일치율 |
| 일본어 구간 | 일본어 질문 검출 재현율 |
| 번역 | 정답 시트 D열 대비 chrF + 일본어 화자 블라인드 비교(가능하면) |
| 자원 | 1시간 환산 처리 시간, 최대 VRAM. 3대 모두에서 측정 |

**결정 규칙**: sherpa-onnx(Java 단일) 결과가 Python 경로와 비슷하면 Java 단일로 간다. 차이가 크면 Python 워커로 간다. "비슷함"의 기준은 샘플 결과를 보고 함께 정한다.

## 8. 마일스톤

| 단계 | 내용 | 완료 기준 |
|---|---|---|
| M0 | PoC | 로컬 STT·화자 구분·번역 모델 결정 |

| M2 | 로컬 STT·화자 구분 | 영상 → 행(구간 1개 = 행 1개)이 검수 화면에 뜸 |

## 9. 미결 사항

- 참고 이미지(시트 디자인). M5 전에 필요
- 1시간 넘는 타임라인 표기
- 일본어 질문 영역(QUESTION_JA)의 시트 배치: 답변 바로 위 병합 셀로 가정
- 발로란트 용어집 원본(한↔일). 없으면 직접 구축
- pyannote 모델 재배포 조건(HF 게이트). Python 워커로 결정되면 확인
- `drive.file` 권한으로 사용자가 고른 기존 폴더에 시트를 만들 수 있는지. M5 PoC
- Windows CUDA 빌드의 cudart DLL 번들 크기, Vulkan 빌드와의 속도 차이
- 라이선스. 공개 저장소인데 아직 없어서 "모든 권리 보유" 상태다. 같이 배포할 ffmpeg(LGPL), llama.cpp(MIT), JavaFX(GPL + Classpath Exception)와 맞아야 한다
- 설치파일 배포 채널. M1은 Actions 아티팩트로만 올린다(D-024). 공개 배포 채널은 라이선스와 함께 정한다
