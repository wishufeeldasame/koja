# koja 설계 (v0.1, 2026-11-23)

요구사항 원문: `docs/private/요구사항.md`(비공개, 로컬 전용)

## 1. 확정 사항

| 항목 | 결정 |
|---|---|
| 목적 | 편집용 **초벌 기록**. 영상의 발언을 타임테이블로 빠짐없이 기록하고, 고르고 고치는 일은 편집자가 앱에서 한다. 빠짐없음(재현율)과 시간 정확도가 먼저이고, 정제는 추천까지만 한다(D-032) |
| 형태 | 윈도우·맥 설치형 데스크톱 앱, 개인 사용(D-034) |
| 언어·UI | Java 25 LTS + JavaFX, Gradle, jpackage(.msi / .dmg) |
| 빌드 | GitHub Actions 매트릭스(windows-latest, macos-latest arm64). jpackage는 크로스 빌드 불가 |
| 서명 | 1차는 미서명 + 설치 안내 문서 |
| AI 단계 | 단계마다 로컬/외부 선택. **로컬을 먼저 구현**, 외부 어댑터는 나중 |
| 로컬 LLM | llama.cpp `llama-server`를 앱에 내장(Win CUDA / Mac Metal). OpenAI 호환 API로 호출 |
| 로컬 STT·화자 구분 | STT는 whisper.cpp `whisper-server`(large-v3-turbo) 내장, VAD·화자 구분은 sherpa-onnx Java (D-039) |
| 검수 | 앱 안에서 먼저(영상 + 표), 이후 Google 시트로 내보내기 |
| 시트 인증 | OAuth Desktop(루프백 + PKCE) + `drive.file` 스코프, 사용자별 구글 계정 |
| 분야 | 발로란트 우선. 용어집은 게임별 파일로 분리해 확장 가능하게 |
| 범위 밖 | 일본어 발화의 한국어 번역(6-3). 나중에 옵션으로 추가 |

각 결정의 이유와 버린 대안은 [결정기록.md](결정기록.md)에 있다.

## 2. 핵심 원칙

1. **타임라인과 한국어 원문은 STT 결과에서만 나온다.** LLM은 STT 구간 ID를 묶고, 분류하고, 번역만 한다. LLM 출력은 코드로 검증한다(모든 구간 ID가 행 또는 무시 목록에 순서대로 한 번씩 쓰였는지). 인터뷰 영상(A형)에서는 문맥으로 질문자와 답변자를 가려 그 발언만 행으로 만들고, 그 외(번역가의 통역, 관계자 잡담)는 무시 목록(`ignoredSegIds`, M3에서 모델에 추가)에 넣는다(D-031). 무시한 구간은 시트로 내보내지 않지만, 검수 화면에서는 "숨긴 구간"으로 접어 두고 펼쳐서 행으로 되살릴 수 있다(D-033).
2. **단계마다 결과를 파일로 남긴다.** 실패하거나 엔진을 바꿨을 때 그 단계부터 다시 돌릴 수 있게.
3. **GPU는 한 번에 한 단계만 쓴다.** STT → 화자 구분 → LLM 순서로 돌리고, 각 엔진은 단계가 끝나면 내린다. 8GB 카드 기준으로 맞춘다.
4. **모르면 비워 두고 표시한다.** 화자 이름, 청취 불명 구간은 추측하지 않고 플래그를 단다.
5. **빠뜨리는 것보다 남기는 게 낫다.** 편집자는 남는 행을 바로 지울 수 있지만, 빠진 발언은 영상을 다시 돌려 찾아야 한다. 자동으로 지우지 않고, 불필요해 보이는 행은 표시만 한다(D-032).

## 3. 구조

```
JavaFX 앱 (한 프로세스)
├─ ui        가져오기 · 진행 상황 · 검수 화면(영상+표) · 설정
├─ core      Project 모델, project.json 저장/로드, 파이프라인 실행, 검증기
├─ engine    단계별 인터페이스 + 로컬/외부 구현
│   ├─ Transcriber   (로컬: whisper-server / 외부: Soniox, CLOVA …)
│   ├─ Diarizer      (로컬: sherpa-onnx / 외부: STT 내장)
│   ├─ LlmClient     (로컬: llama-server / 외부: Gemini, Claude, OpenAI)
│   └─ FrameReader   (로컬: llama-server 비전 모델 / 외부: Gemini)
├─ media     ffmpeg 호출(오디오 추출, 프록시 MP4, 프레임 추출)
├─ runtime   내장 바이너리·모델 관리(다운로드, 체크섬, 실행/종료)
└─ export    Google Sheets 출력
```

Gradle 단일 모듈(`app/`, Java 모듈 `koja`), 패키지 `koja.*`로만 나눈다. 쪼갤 이유가 생기면 그때 모듈로 뺀다.

### 내장 바이너리와 모델

- 앱 번들: `ffmpeg`(LGPL 빌드), `llama-server`, `whisper-server`(둘 다 Win: CUDA 빌드 + cudart DLL / Mac: Metal 빌드). CI에서 고정 버전과 체크섬으로 받아 넣는다.
- sherpa-onnx(VAD·화자 구분)는 Java 의존성으로 앱 안에서 돈다(CPU).
- 모델(GB 단위)은 번들에 넣지 않는다. 첫 실행 때 Hugging Face에서 받아 사용자 데이터 폴더에 둔다.
  - Win: `%LOCALAPPDATA%\koja\models` / Mac: `~/Library/Application Support/koja/models`

## 4. 처리 흐름

| # | 단계 | 입력 → 출력 | 비고 |
|---|---|---|---|
| 1 | 가져오기 | 영상 → `audio.wav`(16kHz mono), `proxy.mp4`(H.264 720p, GOP 1초) | 프록시는 검수 화면 재생용. 원본 포맷 무관 |
| 2 | STT | audio → VAD 구간 → `stt.json` (구간: id, startMs, endMs, text, lang, 단어 시간) | VAD로 무음·BGM 구간 환각 억제. 자동 언어로 1회 |
| 3 | 화자 구분 | audio → `diar.json` (화자 턴) → STT 구간에 speakerId 부여(겹침 최대) | 화자 수 범위 지정 가능 |
| 4 | 한국어 재전사 | 한국어가 아닌 언어로 잡힌 구간을 한국어로 고정해 다시 전사, 두 결과 모두 남김 (D-040) | 한·일 섞인 구간에서 한국어 답변이 일본어로 번역돼 사라지는 것 방지 |
| 5 | 구조화 (LLM) | 3~5분 청크 + 앞뒤 겹침 → `rows.json` | 영상 유형 판별, 문장 단위 묶기, 질문/답변 분류, 불확실 플래그 |
| 6 | 화자 이름 (비전) | 화자별 첫 발화 시점 프레임의 하단 크롭 → 이름 후보 | 못 찾으면 `화자 미확인 N` + 플래그 |
| 7 | 번역 (LLM) | rows + 용어집 + 화자표 + 직전 문맥 → 각 행 `ja` | 행 ID 단위 대응 검증 |
| 8 | 검수 | 사람이 앱에서 수정·플래그 해제 | 행 클릭 → 영상 이동 |
| 9 | 내보내기 | Google 시트 생성 + 서식 | `batchUpdate` 1~2회 |

영상 유형(질의응답·자유 발언·혼합, 인터뷰어 국적)은 5단계에서 자동 판별하고, 가져올 때 사용자가 직접 지정할 수도 있다.

## 5. 데이터 모델 (`project.json`)

```jsonc
{
  "version": 1,
  "source": { "path": "...", "durationMs": 3600000 },
  "meta": { "title": "", "topic": "", "participants": [] },
  "videoType": "INTERVIEW_JA | INTERVIEW_KO | FREE | MIXED",
  "speakers": [ { "id": "S1", "name": "선수A", "confirmed": true },
                { "id": "S2", "name": "화자 미확인 1", "confirmed": false } ],
  "sttSegments": [ { "id": 1, "startMs": 398000, "endMs": 401200,
                     "text": "...", "lang": "ko", "speakerId": "S1" } ],
  "rows": [ { "id": "r1",
              "kind": "LINE | QUESTION_KO | QUESTION_JA",
              "startMs": 398000,          // QUESTION_JA 는 null
              "speakerId": "S1",          // QUESTION_JA 는 null
              "ko": "...", "ja": "...",
              "segIds": [1, 2],
              "flags": ["SPEAKER_UNSURE", "TEXT_UNSURE"] } ],
  "glossary": "valorant",
  "stages": { "stt": { "engine": "...", "done": true } }
}
```

- `startMs`는 해당 행 첫 단어의 STT 단어 시간을 그대로 쓴다(VAD 구간 시작이 아님, D-040). LLM이 정하지 않는다.
- 코드: `koja.core.Project`(레코드), 읽기·쓰기는 `ProjectStore`. 저장은 임시 파일에 쓰고 fsync한 뒤 원자적으로 바꿔치기한다(쓰다 죽어도 기존 파일 보존). 원자적 이동이 안 되는 파일시스템이면 저장을 실패시킨다. 읽기·쓰기 모두 같은 검사를 한다: `version`이 정확히 1, `source.path`·`speakers`·`sttSegments`·`rows`가 있어야 한다.
- 표시 형식: `m:ss`, 1시간 넘으면 `h:mm:ss` (**미확정, 기본값**)
- 프로젝트 폴더 = `project.json`이 있는 폴더. 검수 화면은 그 폴더의 `proxy.mp4`를 재생하고, 없으면 `source.path`(상대 경로는 프로젝트 폴더 기준)를 재생한다(D-028). 코드: `koja.core.ProjectFiles`, 시간 표시는 `koja.core.Timecode`.
- 검수 화면(`koja.ui.ReviewView`): 왼쪽 영상, 오른쪽 행 표(시간·종류·화자·한국어·일본어·플래그). 행을 누르면 그 행 `startMs`로 영상이 이동한다(QUESTION_JA는 이동 없음). 한국어·일본어 셀을 고치고 저장(Ctrl/Cmd+S)하면 `rows`만 바뀐다. 저장 안 한 변경이 있으면 닫기·열기 전에 묻는다.

## 6. 로컬 LLM 기본값 (PoC로 확인)

| 장비 | 구조화·비전 | 번역 |
|---|---|---|
| 8GB / 10GB + RAM 32GB | Qwen3.5-9B Q4 (GPU에 전부) | Gemma 4 26B-A4B Q4, MoE 전문가 일부 CPU 오프로드 |
| M5 Pro 24GB | Qwen3.5-9B Q4 | Gemma 4 26B-A4B Q4 (메모리 상한 근처, 청크 작게) |

번역 기본값은 M0 결과(7.2)와 윈도우 실측으로 정한다(D-041 보류). 후보는 Gemma 4 26B-A4B와 Gemma 4 E4B이고, Qwen3.5-9B는 번역에서 가장 낮았다. 구조화·비전 기본값은 아직 재지 않았다.

로컬 번역 품질은 상용 모델보다 낮을 것으로 예상한다(공개 벤치 1건 근거). 번역 단계만 외부로 바꾸는 게 첫 외부 어댑터 후보.

## 7. 0단계 PoC (로컬 엔진 결정)

목적: 같은 샘플로 로컬 후보를 재고 엔진을 고른다. Python 스크립트로 빠르게 하고, 앱 코드와는 분리한다(`poc/`).

**필요 데이터**: `docs/private/샘플요청.md`(비공개)의 A-1(일본인 인터뷰어) 1편 + B(자유 발언) 1편, 각 20분 이상 + 사람이 만든 완성 시트.

| 비교 대상 | 후보 |
|---|---|
| STT | Qwen3-ASR-1.7B, 한국어 파인튜닝판(TeamUNIVA), Whisper large-v3-turbo(whisper.cpp), sherpa-onnx Qwen3-ASR |
| 화자 구분 | pyannote community-1, sherpa-onnx 화자 구분 |
| 번역 | Gemma 4 26B-A4B, Qwen3.5-9B, Gemma 4 E4B (llama-server) |

| 측정 항목 | 방법 |
|---|---|
| 한국어 정확도 | 정답 시트 C열 대비 CER |
| 시간 정확도 | 행 시작 시각 오차 중앙값, 1초 이내 비율 |
| 화자 정확도 | 행 단위 화자 일치율 |
| 일본어 구간 | 일본어 질문 검출 재현율 |
| 번역 | 정답 시트 D열 대비 chrF + 일본어 화자 블라인드 비교(가능하면) |
| 자원 | 1시간 환산 처리 시간, 최대 VRAM. 3대 모두에서 측정 |

**결정 규칙**: sherpa-onnx(Java 단일) 결과가 Python 경로와 비슷하면 Java 단일로 간다. 차이가 크면 Python 워커로 간다. "비슷함"의 기준은 샘플 결과를 보고 함께 정한다.

### 7.1 STT·화자 구분 결과 (2026-11-23, 맥 M5 Pro)

샘플은 A-1형 3편(B형 없음). 스크립트와 방법은 `poc/README.md`. 시트가 정제본이라 CER 대신 내용 포함(재현율)을 1순위로 봤다(D-032). 수치는 샘플 3편 순서.

| 경로 | 시트 행 재현율 | 시간 1초 이내 | 일본어 질문 검출 | 최대 메모리 |
|---|---|---|---|---|
| whisper.cpp large-v3-turbo, 2회 방식 | 0.98 / 1.00 / 0.90 | 0.91 / 0.70 / 0.79 | 0.96~1.00 | 2.0GB |
| Qwen3-ASR 1.7B + ForcedAligner, 2회 방식, 10초 분할 (Python) | 0.98 / 1.00 / 0.90 | 0.89 / 0.73 / 0.79 | 1.00 | 10.9GB |
| sherpa-onnx Qwen3-ASR 1.7B int8, 10초 분할 (Java, 단어 시간 없음) | 0.95 / 0.98 / 0.84 | 0.87 / 0.60 / 0.59 | 1.00 | 5.9GB |

| 화자 구분 (10초 분할 구간 단위 배정) | 선수 일치율 | 최대 메모리 |
|---|---|---|
| sherpa-onnx CAM++ (기준값 0.9) | 1.00 / 0.94 / 0.94 | 0.6GB |
| pyannote community-1 | 1.00 / 0.93 / 0.94 | 7.4GB |

화자를 긴 VAD 구간 단위로 붙이면 일치율이 떨어진다(whisper 2회 + CAM++, 기본 VAD: 0.94 / 0.86 / 0.85). 결과로 whisper.cpp + sherpa-onnx 조합을 골랐다(D-039, D-040). 윈도우 실기 측정(`poc/WINDOWS.md`)은 아직 하지 않았다.

### 7.2 번역 결과 (2026-11-24, 맥 M5 Pro)

입력은 정답 시트 한국어 150행(STT 결과가 아님), 정답은 시트 일본어. `poc/translate.py`가 llama-server(Q4_K_M, 추론 끔)에 8행씩 보내고 앞 4행(원문+번역)을 문맥으로 준다. 응답은 JSON 스키마로 받고 행 ID 대응을 코드로 검증한다. 용어집은 없다.

| 모델 | chrF | 영문 고유명사 유지 | GPU 메모리(추정) | 1시간 영상 환산 |
|---|---|---|---|---|
| Gemma 4 26B-A4B | 30.8 / 27.5 / 31.7 | 0.79 | 17.7GB | 5.7분 |
| Gemma 4 E4B | 30.1 / 25.8 / 31.6 | 0.81 | 3.8~3.9GB | 5.5분 |
| Qwen3.5-9B | 25.6 / 23.2 / 28.0 | 0.67 | 6.4GB | 6.0분 |

시트 일본어가 다듬은 최종본이라 chrF는 참고 지표다. 일본어 화자 블라인드 비교는 하지 않는다. 모델 결정은 윈도우 실측 뒤로 미뤘다(D-041).
