## 1. 확정 사항

| 항목 | 결정 |
|---|---|
| 목적 | 편집용 **초벌 기록**. 영상의 발언을 타임테이블로 빠짐없이 기록하고, 고르고 고치는 일은 편집자가 앱에서 한다. 빠짐없음(재현율)과 시간 정확도가 먼저이고, 정제는 추천까지만 한다(D-032) |
| 형태 | 윈도우·맥 설치형 데스크톱 앱, 개인 사용(D-034) |
| 언어·UI | Java 25 LTS + JavaFX, Gradle, jpackage(.msi / .dmg) |
| 빌드 | GitHub Actions 매트릭스(windows-latest, macos-latest arm64). jpackage는 크로스 빌드 불가 |
| 서명 | 1차는 미서명 + 설치 안내 문서 |
| AI 단계 | 단계마다 로컬/외부 선택. **로컬을 먼저 구현**, 외부 어댑터는 나중 |
| 로컬 LLM | llama.cpp `llama-server`를 앱에 내장(Win CUDA / Mac Metal). OpenAI 호환 API로 호출 |
| 로컬 STT·화자 구분 | STT는 whisper.cpp `whisper-server`(large-v3-turbo) 내장, VAD·화자 구분은 sherpa-onnx Java (D-039) |
| 검수 | 앱 안에서 먼저(영상 + 표), 이후 Google 시트로 내보내기 |
| 시트 인증 | OAuth Desktop(루프백 + PKCE) + `drive.file` 스코프, 사용자별 구글 계정. 리프레시 토큰은 OS 보관소(맥 Keychain / 윈도우 DPAPI, D-056), 클라이언트는 환경 변수(D-058) |
| 분야 | 발로란트 우선. 용어집은 게임별 파일로 분리해 확장 가능하게 |
| 범위 밖 | 일본어 발화의 한국어 번역(6-3). 나중에 옵션으로 추가 |

각 결정의 이유와 버린 대안은 [결정기록.md](결정기록.md)에 있다.

## 2. 핵심 원칙

1. **타임라인과 한국어 원문은 STT 결과에서만 나온다.** LLM은 STT 구간 ID를 묶고, 분류하고, 번역만 한다. LLM 출력은 코드로 검증한다(모든 구간 ID가 행 또는 무시 목록에 순서대로 한 번씩 쓰였는지). 예외: 한국어 후보가 있는 2회 방식 구간은 일본어 질문 행(1차 결과)과 한국어 행(한국어 후보)에 한 번씩 함께 쓸 수 있다. 한·일이 섞인 한 구간에 질문과 답변이 같이 들어 있기 때문이다(D-045). 인터뷰 영상(A형)에서는 문맥으로 질문자와 답변자를 가려 그 발언만 행으로 만들고, 그 외(번역가의 통역, 관계자 잡담)는 무시 목록(`ignoredSegIds`, M3에서 모델에 추가)에 넣는다(D-031). 무시한 구간은 시트로 내보내지 않지만, 검수 화면에서는 "숨긴 구간"으로 접어 두고 펼쳐서 행으로 되살릴 수 있다(D-033).
2. **단계마다 결과를 파일로 남긴다.** 실패하거나 엔진을 바꿨을 때 그 단계부터 다시 돌릴 수 있게.
3. **GPU는 한 번에 한 단계만 쓴다.** STT → 화자 구분 → LLM 순서로 돌리고, 각 엔진은 단계가 끝나면 내린다. 8GB 카드 기준으로 맞춘다.
4. **모르면 비워 두고 표시한다.** 화자 이름, 청취 불명 구간은 추측하지 않고 플래그를 단다.
5. **빠뜨리는 것보다 남기는 게 낫다.** 편집자는 남는 행을 바로 지울 수 있지만, 빠진 발언은 영상을 다시 돌려 찾아야 한다. 자동으로 지우지 않고, 불필요해 보이는 행은 표시만 한다(D-032).

## 3. 구조

```
JavaFX 앱 (한 프로세스)
├─ ui        가져오기 · 진행 상황 · 검수 화면(영상+표) · 설정
├─ core      Project 모델, project.json 저장/로드, 파이프라인 실행, 검증기
├─ engine    단계별 인터페이스 + 로컬/외부 구현
│   ├─ Transcriber   (로컬: whisper-server / 외부: Soniox, CLOVA …)
│   ├─ Diarizer      (로컬: sherpa-onnx / 외부: STT 내장)
│   ├─ LlmClient     (로컬: llama-server / 외부: Gemini, Claude, OpenAI)
│   └─ FrameReader   (로컬: llama-server 비전 모델 / 외부: Gemini)
├─ media     ffmpeg 호출(오디오 추출, 프록시 MP4, 프레임 추출)
├─ runtime   내장 바이너리·모델 관리(다운로드, 체크섬, 실행/종료)
└─ export    Google Sheets 출력
```

엔진 계약(D-049): 네 인터페이스는 `koja.engine.Engine`(`AutoCloseable`, `name()`)을 잇는다. 파이프라인(`koja.engine.Pipeline`)이 단계 직전에 엔진을 열고 단계가 끝나면 바로 닫아 GPU를 내린다(동시에 두 엔진을 열지 않음). 실행 전체(project.json 읽기~마지막 저장)를 앱 전체 잠금 하나로 감싸, 두 실행이 엔진을 동시에 열거나 같은 프로젝트 파일을 엇갈려 고치지 않는다. 진행률 콜백 안에서 다시 실행하면 거부한다. 화자 구분 `done`은 화자표 초기화와 같은 저장으로 기록한다. 작업 메서드는 진행률을 `DoubleConsumer`(0~1, 모르면 -1)로 알리고, 취소는 스레드 interrupt → `InterruptedException`이다(단계 사이·저장 중 interrupt도 같은 예외). `Transcriber.transcribe(audio)` → `SttResult`(VAD 포함), `Diarizer.diarize(audio)` → `DiarResult`, `LlmClient.complete(Request)` → `Response`(다중 메시지·JSON 스키마 강제·`usage`·`finishReason`, `ContextLengthExceededException`·`OutOfMemoryException`·`OutputTruncatedException`, 기본 `complete(system, user)` 유지; 로컬 구현 `LlamaServerClient`는 Gemma 4 E4B 기본 / 26B 선택, `-ngl auto`, `--reasoning off`, 8K 컨텍스트, D-066·D-067), `FrameReader.read(image, prompt)` → 문자열(못 읽으면 빈 문자열). 파이프라인은 STT → 화자 구분 → 화자 붙이기 → M2 행 만들기(구간 1개 = 행 1개, `koja.core.SegmentRows`, D-071)까지다. 로컬 엔진 조립(Silero VAD + whisper-server, CAM++)과 필요한 모델 목록은 `koja.engine.LocalEngines`. 처리 창(`koja.ui.PipelineDialog`)이 빠진 모델을 용량 확인 후 받고, 단계 진행률·취소를 보여 주며, 작업 스레드가 엔진을 내린 뒤 닫힌다(D-072).

로컬 STT 구현(D-061): `koja.engine.whisper.WhisperTranscriber`는 VAD(`WhisperTranscriber.Vad`, sherpa 구현은 W2-3)를 생성자로 받고, 구간마다 audio.wav를 잘라 whisper-server에 `language=auto`로 1회, 결과가 `ko`가 아니면 `language=ko`로 1회 더 보내 `ko` 후보로 둔다. 1회차가 빈 구간은 버리고, 단어 시간은 서버 토큰 시각 + 구간 시작(구간 안으로 묶음), 언어는 코드(`ko`·`ja`·`en`·`zh`)로 바꾼다. `close()`가 서버를 내린다. 엔진 시작 중 취소(`LocalServer`의 `CancellationException`)는 `Pipeline`이 `InterruptedException`으로 바꾼다.

Gradle 단일 모듈(`app/`, Java 모듈 `koja`), 패키지 `koja.*`로만 나눈다. 쪼갤 이유가 생기면 그때 모듈로 뺀다.

### 내장 바이너리와 모델

- 앱 번들: `ffmpeg`(LGPL 빌드. 윈도우는 BtbN `win64-lgpl`, 맥은 CI에서 소스 빌드, 고지 파일 동봉. D-037). `scripts/bundle_ffmpeg.sh`가 고정 버전·SHA-256으로 `app/build/ffmpeg`에 만들고 검사하며, jpackage `--app-content`로 맥 `Contents/ffmpeg/`, 윈도우 `<설치 폴더>/ffmpeg/`에 들어간다. 앱은 번들 → `KOJA_FFMPEG` → PATH 순서로 찾는다(D-042).
- 앱 번들: `llama-server`(llama.cpp `b12655`, 맥 최소 macOS 13.3 이상, D-065·D-069). `scripts/bundle_llama.sh`가 맥은 공식 arm64 Metal 빌드에서 필수 바이너리·dylib만, 윈도우는 공식 CUDA 12.4 빌드에서 llama·ggml·OpenMP DLL만 골라 `app/build/llama`에 만들고(공유 CUDA 런타임은 `app/build/cuda`, D-060), jpackage가 맥 `Contents/llama/`, 윈도우 `<설치 폴더>/llama/`에 넣는다. 앱은 `koja.runtime.LlamaServer`로 번들 → `KOJA_LLAMA_SERVER` → PATH 순으로 찾고, 윈도우에서는 형제 `cuda/`를 자식 `PATH` 맨 앞에 붙인다.
- 앱 번들: `whisper-server`(whisper.cpp b5907, D-059). `scripts/bundle_whisper.sh`가 맥은 소스를 Metal 정적 빌드(셰이더 내장, 실행 파일 하나), 윈도우는 공식 CUDA 12.4 빌드에서 필요한 DLL만 골라 `app/build/whisper`에 만들고, jpackage가 맥 `Contents/whisper/`, 윈도우 `<설치 폴더>/whisper/`에 넣는다. 앱은 번들 → `KOJA_WHISPER_SERVER` → PATH 순서로 찾는다(`koja.runtime.WhisperServer`).
- 윈도우 CUDA 런타임 DLL(`cudart64_12`·`cublas64_12`·`cublasLt64_12`, 약 575MB)은 `<설치 폴더>/cuda/` 한곳에 두고 whisper-server·llama-server가 함께 쓴다. 서버를 띄울 때 `cuda/`를 자식 프로세스 `PATH` 앞에 붙인다. 서버 폴더에는 자기 `ggml*.dll`만 둔다(D-060). Vulkan 빌드는 쓰지 않는다(D-060).
- 고지: 번들 바이너리마다 자기 폴더 안에 `NOTICE.txt`(이름·버전·라이선스·출처·SHA-256)와 라이선스 전문을 둔다(`ffmpeg/`, `whisper/`, `cuda/`, `llama/`, `sherpa-native/`, D-059·D-062).
- sherpa-onnx(VAD·화자 구분)는 Java 의존성(`v2.0.3`, GitHub Releases에서 SHA-256 검증 뒤 빌드 때 `module-info.class`를 주입해 명시 모듈 `sherpa.onnx.jvm`으로 패키징)으로 앱 안에서 돈다(CPU, D-062). 플랫폼별 네이티브 동적 라이브러리와 고지(`NOTICE.txt`·라이선스 전문)는 jpackage `--app-content`로 맥 `Contents/sherpa-native/`, 윈도우 `<설치 폴더>/sherpa-native/`에 들어가며, `SherpaNative`가 `AppPaths.bundledDirectory("sherpa-native")`로 경로를 지정해 적재한다. ONNX 모델 3종(Silero VAD, pyannote segmentation-3.0, CAM++)은 `ModelStore`로 받는다(`SherpaModels`).
- 모델(GB 단위)은 번들에 넣지 않는다. 첫 실행 때 Hugging Face(또는 공식 릴리스)에서 받아 사용자 데이터 폴더에 둔다.
  - Win: `%LOCALAPPDATA%\koja\models` / Mac: `~/Library/Application Support/koja/models`
- `koja.runtime` 공통 인프라: OS 분기는 이 패키지 한곳에만 둔다.
  - `AppPaths`: OS별 데이터·모델 폴더(`dataDir`, `modelsDir`), 실행 파일 확장자(`.exe`), `jpackage.app-path` 기준 번들 폴더·실행 파일 탐색(`bundledDirectory`, `bundledExecutable`).
  - `ModelStore`: Java `HttpClient`로 모델 다운로드, `.part` 임시 파일과 `Range` 이어 받기·취소·수신 타임아웃, `.lock` 파일 잠금 직렬화, 스트리밍 SHA-256 검증, `fsync` 후 `ATOMIC_MOVE`(D-050).
  - `WhisperServer`: 번들 whisper-server 위치, 실행 인자, 윈도우 `cuda/` PATH, 모델 명세(large-v3-turbo, D-059·D-060).
  - `LlamaServer`: 번들 llama-server 위치, 상대 경로 절대화, 부모 환경 `LLAMA_ARG_*`·`LLAMA_LOG_*`·`LLAMA_API_KEY` 격리, 윈도우 `cuda/` PATH(D-065·D-066·D-069).
  - `LocalServer`: `whisper-server`·`llama-server` 공용 프로세스 수명주기. `127.0.0.1` 동적 포트 할당(또는 자식 바인딩 포트 로그 추출), 리스너 소유 프로세스 검증, 시스템 프록시 우회(`ProxySelector.of(null)`), UTF-8 로그 드레인, 제한 시간 내 헬스체크, 종료 시 프로세스 트리 정리 및 생존 여부 확인으로 GPU 메모리 해제 보장(D-051).

## 4. 처리 흐름

| # | 단계 | 입력 → 출력 | 비고 |
|---|---|---|---|
| 1 | 가져오기 | 영상 → `audio.wav`(16kHz mono), `proxy.mp4`(H.264 720p, GOP 1초) | 프록시는 검수 화면 재생용. 원본 포맷 무관. H.264는 OS 인코더(맥 VideoToolbox, 윈도우 NVENC → Media Foundation), 모두 실패하면 프록시 없이 진행(D-038) |
| 2 | STT | audio → VAD 구간 → `stt.json` (구간: id, startMs, endMs, text, lang, 단어 시간, 4단계 한국어 후보 `ko`) | VAD로 무음·BGM 구간 환각 억제. 자동 언어로 1회 |
| 3 | 화자 구분 | audio → `diar.json` (화자 턴) → STT 구간에 speakerId 부여(겹침 최대) | 화자 수 범위 지정 가능 |
| 4 | 한국어 재전사 | 한국어가 아닌 언어로 잡힌 구간을 한국어로 고정해 다시 전사, 두 결과 모두 남김 (D-040) | 한·일 섞인 구간에서 한국어 답변이 일본어로 번역돼 사라지는 것 방지 |
| 5 | 구조화 (LLM) | 1차 언어 인식 절 분할(`clause`) → 1단계 영상 분석(`videoType`·화자 역할) → 2단계 최대 24구간·3분 청크(앞뒤 6구간·30초, 8K) 평탄 1:1 스키마 → `rows.json` | 구간 ID 고정 순서·과병합 방지·D-045 이중 검증, 불확실 플래그(D-053~D-055) |
| 6 | 화자 이름 (비전) | 화자별 첫 발화 시점 프레임의 하단 크롭 → 이름 후보 | 못 찾으면 `화자 미확인 N` + 플래그 |
| 7 | 번역 (LLM) | rows + 용어집 + 화자표 + 직전 문맥 → 각 행 `ja` | 행 ID 단위 대응 검증 |
| 8 | 검수 | 사람이 앱에서 수정·플래그 해제 | 행 클릭 → 영상 이동 |
| 9 | 내보내기 | Google 시트 생성 + 서식 | `batchUpdate` 1~2회 |

영상 유형(질의응답·자유 발언·혼합, 인터뷰어 국적)은 5단계에서 자동 판별하고, 가져올 때 사용자가 직접 지정할 수도 있다.

### 시트 구성 (9단계 내보내기)

요구사항(비공개) 9장을 따른다. 머리글은 일본어로 쓴다.

| 열 | 머리글 | 값 (`rows`) |
|---|---|---|
| A | タイムライン | `startMs`를 `m:ss`로(5장 표시 형식). 실제 발화 시작 시각이다 |
| B | 話者 | `speakerId`의 화자 이름. 미확인이면 `화자 미확인 N` |
| C | 韓国語 | `ko` |
| D | 日本語 | `ja` |

- 시트 위쪽에 영상 정보(`meta`: 제목, 주제, 출연자)를 쓴다. 영상에서 확인한 정보만 쓴다.
- `kind`별 표시:
  - `LINE`: 기본 배경
  - `QUESTION_KO`(한국인 인터뷰어 질문): 일반 행과 같은 열에 쓰고, 노란 계열 배경으로 구분한다
  - `QUESTION_JA`(일본인 인터뷰어 질문): A·B열 없이 질문 문장(`ja`)만 노란 계열 질문 영역에 쓴다. 위치는 9장 미결
- 플래그별 표시: `SPEAKER_UNSURE`는 주황 계열, `TEXT_UNSURE`는 빨간 계열. 무엇을 확인할지 셀에 남긴다. 플래그가 있어도 확인된 한국어·일본어는 채운다.
- 무시 목록(`ignoredSegIds`)의 구간은 내보내지 않는다(2장 원칙 1).
- 색·글꼴·열 너비 같은 세부 서식은 참고 이미지를 받은 뒤 정한다(9장 미결).

## 5. 데이터 모델 (`project.json`)

```jsonc
{
  "version": 1,
  "source": { "path": "...", "durationMs": 3600000 },
  "meta": { "title": "", "topic": "", "participants": [] },
  "videoType": "INTERVIEW_JA | INTERVIEW_KO | FREE | MIXED",
  "speakers": [ { "id": "S1", "name": "선수A", "confirmed": true },
                { "id": "S2", "name": "화자 미확인 1", "confirmed": false } ],
  "sttSegments": [ { "id": 1, "startMs": 398000, "endMs": 401200,
                     "text": "...", "lang": "ja", "speakerId": "S1",
                     "words": [ { "startMs": 398100, "endMs": 398700, "text": "..." } ],
                     "ko": { "text": "...", "words": [ ... ] } } ],   // ko: 한국어 후보, 없으면 null
  "rows": [ { "id": "r1",
              "kind": "LINE | QUESTION_KO | QUESTION_JA",
              "startMs": 398000,          // QUESTION_JA 는 null
              "speakerId": "S1",          // QUESTION_JA 는 null
              "ko": "...", "ja": "...",
              "segIds": [1, 2],
              "flags": ["SPEAKER_UNSURE", "TEXT_UNSURE"] } ],
  "ignoredSegIds": [3, 4],        // 무시 목록(D-031·D-033), 없으면 []
  "glossary": "valorant",
  "stages": { "stt": { "engine": "...", "done": true } }
}
```

- 버전 정책(D-048): 선택 항목 추가는 `version`을 올리지 않는다. 새 항목이 없는 옛 파일은 빈 값으로 읽는다(`ignoredSegIds`·`words` → `[]`, `ko` → null). 옛 파일을 못 읽게 되는 변경에서만 올린다.
- `sttSegments`(D-048): `text`·`lang`·`words`는 자동 언어 1차 결과, `ko`는 `lang`이 한국어가 아닐 때 한국어로 고정해 다시 전사한 후보(`text`, `words`)다(D-040). 단어 시간은 영상 시작 기준 ms. 한국어 구간은 `ko`가 null이다.
- 단계 결과 파일(프로젝트 폴더, D-048). 엔진은 자기 단계 파일만 만들고, `project.json`은 파이프라인이 고친다. 둘 다 `version` 1, 저장은 `project.json`과 같은 원자적 쓰기. 코드: `koja.core.StageStore`.
  - `stt.json`: `{ "version": 1, "engine": "...", "segments": [ 위 sttSegments 구간, speakerId는 null ] }`. 구간 `id`는 1부터 엄격히 오름차순, `speakerId`는 null, 구간·단어(`words`, `ko.words`) 모두 `0 ≤ startMs ≤ endMs`, `text` 필수. 읽기·쓰기 때 검사한다. 단계 파일은 앱이 모든 항목을 쓰므로 읽을 때 빠진 항목·숫자 null을 거부한다(`project.json`은 옛 파일 때문에 거부하지 않음).
  - `diar.json`: `{ "version": 1, "engine": "...", "turns": [ { "startMs", "endMs", "speaker" } ] }`. `speaker`는 엔진 임의 라벨. 파이프라인이 구간마다 단어 구간 합집합(`words`가 있으면 우선, 없거나 겹침이 0이면 전체 구간)과 겹침이 가장 긴 라벨을 붙이고(같은 라벨의 겹친 턴은 한 번만 셈, 겹침 없으면 null, D-064), 라벨을 처음 나온 순서로 `S1`, `S2` …로 바꿔 화자표에 `화자 미확인 N`(confirmed false)으로 넣는다. 같은 `diar.json`을 다시 쓸 때는 사람이 고친 화자표 항목을 그대로 두고, 화자 구분을 새로 돌렸으면 그 id들의 항목을 미확인으로 다시 만든다(같은 `S1`이 다른 사람일 수 있음). 5단계 구조화(`clause` 분할)에서는 `diar.json` 턴을 단어 시각에 직접 매칭한다(D-054·D-064).
  - `stages.stt`·`stages.diar`가 `done`이고 결과 파일이 있으면 다시 돌릴 때 그 단계를 건너뛴다.
  - `stages.rows`(M2 행, D-071): 화자 구분을 새로 돌렸거나 `stages.rows`가 없을 때만 `rows`를 구간 1개 = 행 1개로 다시 만들고 `ignoredSegIds`를 비운다. STT를 새로 저장할 때 같은 저장에서 `stages.rows`를 지운다(사이에서 멈춰도 옛 행이 새 구간 id를 가리키지 않게). 그 밖에는 사람이 고친 행을 그대로 둔다. 행: `ko`는 한국어 구간이면 `text`, 아니면 한국어 후보 `ko.text`(없으면 빈 값), `ja`는 일본어 구간의 1회차 원문, `startMs`는 고른 텍스트의 첫 단어 시각. 한국어가 아니거나 `ko`가 비면 `TEXT_UNSURE`, 화자가 없거나 미확인이면 `SPEAKER_UNSURE`.
- `startMs`는 해당 행 첫 단어의 STT 단어 시간을 그대로 쓴다(VAD 구간 시작이 아님, D-040). LLM이 정하지 않는다.
- 코드: `koja.core.Project`(레코드), 읽기·쓰기는 `ProjectStore`. 저장은 임시 파일에 쓰고 fsync한 뒤 원자적으로 바꿔치기한다(쓰다 죽어도 기존 파일 보존). 원자적 이동이 안 되는 파일시스템이면 저장을 실패시킨다. 읽기·쓰기 모두 같은 검사를 한다: `version`이 정확히 1, `source.path`·`speakers`·`sttSegments`·`rows`가 있어야 한다.
- 표시 형식: `m:ss`, 1시간 넘으면 `h:mm:ss` (**미확정, 기본값**)
- 프로젝트 폴더 = `project.json`이 있는 폴더. 검수 화면은 그 폴더의 `proxy.mp4`를 재생하고, 없으면 `source.path`(상대 경로는 프로젝트 폴더 기준)를 재생한다(D-028). 코드: `koja.core.ProjectFiles`, 시간 표시는 `koja.core.Timecode`.
- 가져오기(파일 메뉴 → 가져오기): 영상 선택 → 프로젝트 폴더 선택(`project.json`·`proxy.mp4`가 없는 폴더) → `koja.media.Importer`가 ffmpeg를 두 번 돌려 `audio.wav`, `proxy.mp4`를 만든다(임시 `.part` 파일에 쓰고 둘 다 끝나면 이름 바꿈, 취소·실패 시 이번 실행의 임시 파일만 지움, 같은 이름 파일이 있으면 시작하지 않음, 저장 실패 시 두 파일을 지움). 오디오가 영상보다 늦게 시작해도 WAV는 0초부터 무음을 채워 STT 시간이 영상 시간과 같다(`aresample=async=1:first_pts=0`) → `sttSegments`·`rows`가 빈 `project.json`을 저장 → 검수 화면 → 바로 처리 창(STT·화자 구분·행 만들기, D-072). 열린 프로젝트는 처리 메뉴 → 전사·화자 구분 실행(Ctrl/Cmd+R)으로 이어 한다. ffmpeg 위치와 인코더 순서는 `koja.runtime.Ffmpeg`(지금은 `KOJA_FFMPEG` 또는 `PATH`).
- 검수 화면(`koja.ui.ReviewView`): 왼쪽 영상, 오른쪽 행 표(시간·종류·화자·한국어·일본어·플래그). 행을 누르면 그 행 `startMs`로 영상이 이동한다(QUESTION_JA는 이동 없음). 한국어·일본어 셀을 고치고 저장(Ctrl/Cmd+S)하면 `rows`만 바뀐다. 저장 안 한 변경이 있으면 닫기·열기 전에 묻는다.

- 세 번째 샘플의 재현율 손실은 답변 구간을 QUESTION_JA로만 넣었거나 무시한 경우다. Qwen은 선수 화자 구간을 14~22% 무시했다(D-032 빠짐없음 위반).
- 처음 검증 규칙(구간마다 행 또는 무시 목록에 한 번)으로는 E4B가 첫 샘플 6청크 중 3청크를 3번 안에 맞추지 못했다. 한국어 후보가 있는 구간을 QUESTION_JA(일본어)와 LINE(한국어 후보)에 함께 썼기 때문이다. 표의 수치는 이것을 허용한 규칙으로 잰 값이다.
- 프롬프트는 첫 판 하나만 썼다. 두 모델 모두 이 방식 그대로는 시트 행 구성에 못 미치므로, M3에서 출력 형식(구간별 분류 + 새 행 시작 표시 등)과 구간 단위를 다시 정한다.
